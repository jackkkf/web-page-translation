# 人工验收清单

单测能覆盖逻辑，覆盖不了"真实网页长什么样"。每次发版前按此清单走一遍。

## 加载未打包的扩展

```bash
npm run build          # 或 npm run dev（带热更新）
```

- Chrome / Edge：`chrome://extensions` → 开发者模式 → 加载已解压的扩展 → 选 `.output/chrome-mv3`
- Firefox：`about:debugging#/runtime/this-firefox` → 临时载入附加组件 → 选 `.output/firefox-mv2/manifest.json`
- 或用 `npm run dev` / `npm run dev:firefox` 自动打开带扩展的浏览器

## A. 安装与权限

- [ ] 安装时**没有**「读取和更改您在所访问网站上的所有数据」提示
- [ ] 扩展详情页的权限列表只有存储、右键菜单和 4 个翻译服务域名
- [ ] 开启「自动翻译」时弹出全站权限授权请求；拒绝后有明确提示且开关未打开
- [ ] 关闭「自动翻译」后，浏览器权限面板中的全站权限已被撤回

## B. 站点矩阵

每个站点验证：译文位置正确、原文可读、代码块未被翻译、还原后与原始页面一致。

| 站点                     | 考察点                              |
| ------------------------ | ----------------------------------- |
| Wikipedia 英文条目       | 长文、多层嵌套、表格                |
| MDN 文档                 | 大量行内 `<code>`，不能被翻译       |
| GitHub issue / PR 页面   | SPA 路由切换、代码块、diff 视图     |
| Hacker News              | 密集短文本、`<table>` 布局          |
| Reddit                   | 无限滚动、动态加载                  |
| Stack Overflow 问答      | 代码块与正文混排                    |
| arXiv 摘要页             | 数学公式（`<math>` 不能翻）         |
| 一个 Vue/React 官网      | 深色模式下译文样式是否可读          |
| 一个日文站点（如 Qiita） | 日文 → 中文，验证不被误判为已是中文 |
| 一个中文站点             | 目标语言为中文时应该几乎不翻译      |

## C. 核心功能

- [ ] 点击图标 →「翻译此页面」，译文出现在每段原文下方
- [ ] 长页面首屏只翻译可见区域；滚动时新内容被增量翻译
- [ ] 再次点击「显示原文」，页面恢复到与翻译前完全一致
- [ ] `Alt+A` 切换译文/原文
- [ ] 右键菜单「翻译/还原此页面」生效
- [ ] 切换引擎 → 「重新翻译」→ 译文来自新引擎
- [ ] 切换目标语言 → 「重新翻译」→ 译文语言正确
- [ ] 5 种译文样式与 2 种展示模式都正常
- [ ] 「仅显示译文」模式下还原能恢复原文
- [ ] 站点规则「从不翻译」生效；「始终翻译」在授权后生效
- [ ] 缓存统计有变化；清空缓存后重新翻译会重新请求

## D. 异常路径

- [ ] 断网后翻译：段落原位显示「网络请求失败」，页面不崩、原文不丢
- [ ] 选百度但不填密钥：提示「该引擎需要先在设置中填写 API 密钥」
- [ ] 填错百度密钥：提示鉴权失败
- [ ] 主引擎不可用（可用浏览器 DevTools 的请求拦截模拟）：自动降级到备用引擎
- [ ] 在 `chrome://extensions` 等特权页打开 popup：提示「浏览器内置页面不允许扩展运行」
- [ ] 重载扩展后在旧页面点翻译：给出「请刷新页面后重试」而不是静默失败

## E. 性能观察

- [ ] 在 Wikipedia 长条目上翻译，DevTools Network 里首屏请求数与可见段落数相当，而非全文段落数
- [ ] 翻译过程中页面滚动不卡顿
- [ ] 内容脚本产物 < 50 KB，background < 60 KB（构建输出里可见）
