# AI 辅助开发工作流

这个项目预设大部分代码由 AI 助手（Cursor / Claude Code / Codex 等）编写。以下是为此设计的约束体系。

## 1. 核心思路

AI 写代码的瓶颈不是生成速度，而是**它不知道这个项目的隐性约束**，以及**改错了没人立刻发现**。所以工程上做两件事：

1. **把隐性约束写成文件**，让任何 AI 在任何会话开始时都能读到（`AGENTS.md` + ADR）
2. **把正确性变成可执行的检查**，让 AI 自己就能发现改错了（类型 → lint → 测试 → 构建）

## 2. 约束文件的分工

| 文件                       | 谁读           | 放什么                                 | 不放什么                  |
| -------------------------- | -------------- | -------------------------------------- | ------------------------- |
| `AGENTS.md`（根目录）      | 所有 AI 工具   | 命令、结构、红线、约定、测试与提交要求 | 背景故事、设计推导过程    |
| `docs/decisions/NNNN-*.md` | 人 + AI 按需读 | 为什么这么选、代价是什么、何时该复审   | 操作步骤                  |
| `docs/architecture.md`     | 人 + AI 按需读 | 上下文约束、链路、关键取舍             | API 逐个说明              |
| `.cursor/rules/*.mdc`      | Cursor         | 按文件路径触发的细化规则               | 与 `AGENTS.md` 重复的内容 |

**规则**：`AGENTS.md` 保持在 150 行以内。超了就说明内容该下沉到 ADR 或 Cursor 规则。它每次会话都会消耗上下文，长度就是成本。

**规则**：不维护多份互相冲突的指令文件。`CLAUDE.md` 等工具专属文件如需存在，就软链接到 `AGENTS.md`。

## 3. 单次任务的标准流程

```
1. 描述意图与验收标准，而不是描述实现步骤
2. AI 先读相关文档与现有代码（不要让它凭空猜项目约定）
3. 改动尽量小且聚焦，一个 PR 一件事
4. 跑 npm run verify
5. 人工 review 重点看：权限、网络请求位置、错误处理、是否偷偷加依赖
6. 文档与代码同 PR 更新
```

### 提示词模板

```
任务：<要达成什么>
验收标准：
  - <可验证的条件 1>
  - <可验证的条件 2>
约束：遵守 AGENTS.md；不要修改 <不该动的范围>
完成后跑 npm run verify 并把结果贴出来
```

### 反模式

| 反模式                   | 后果                                                 |
| ------------------------ | ---------------------------------------------------- |
| "顺便优化一下其他地方"   | 改动范围爆炸，review 失效                            |
| 让 AI 自行决定加什么依赖 | 悄悄引入体积大或有许可风险的包                       |
| 测试失败就改测试断言     | 掩盖真实缺陷。先判断是实现错还是断言错，再决定改哪边 |
| 只看"跑通了"不看 diff    | 权限、网络位置这类问题不会体现在功能上               |

## 4. 四道自动化关卡

| 关卡 | 命令                | 拦住什么                                     |
| ---- | ------------------- | -------------------------------------------- |
| 类型 | `npm run compile`   | 未处理的 undefined、接口误用、类型漂移       |
| lint | `npm run lint`      | 未使用变量、`any`、`console.log`、hooks 误用 |
| 测试 | `npm run test`      | 引擎解析、译文对齐、DOM 遍历、还原逻辑的回归 |
| 构建 | `npm run build:all` | 三浏览器产物与 manifest 生成                 |

CI 额外跑一道**权限守卫**（`scripts/check-manifest.mjs`）：直接读构建产物的 manifest，断言没有 `content_scripts`、没有 `<all_urls>` 类 host 权限、没有多余权限。这是唯一一条"AI 无法通过改代码绕过"的红线检查 —— 它检查的是构建结果，不是源码。

## 5. 保持文档不腐坏

文档过期比没有文档更危险，AI 会照着过期的说明改错。

| 触发条件                | 必须同步更新                                      |
| ----------------------- | ------------------------------------------------- |
| `package.json` 脚本变更 | `AGENTS.md` 的命令小节                            |
| 新增/删除引擎           | `docs/research/translation-engines.md`、`meta.ts` |
| 权限变更                | ADR-0002、`docs/store/publishing-checklist.md`    |
| 存储结构变更            | `docs/architecture.md` 第 5 节 + storage version  |
| 目录结构变更            | `AGENTS.md` 结构小节 + `docs/architecture.md`     |

**定期审计**：每个迭代结束时，让 AI 执行一次一致性检查：

```
审计 AGENTS.md 与 docs/ 是否与代码一致，逐条列出：
1. 提到的命令是否都存在于 package.json
2. 提到的文件路径是否都还存在
3. 提到的依赖版本是否与 package-lock.json 一致
4. 有没有新增的重要模块没被文档提到
对每个问题给出最小修复建议，优先删除或移动，而不是继续加内容。
```

## 6. 人工必须把关的部分

自动化管不到的地方：

- **权限与隐私**：任何 manifest 变更、任何新的网络请求目标
- **依赖引入**：体积、许可、维护状态
- **交互与文案**：AI 写的 UI 文案经常不像人话
- **真实站点验收**：单测过了不等于在真实网页上不炸，按 `docs/testing/manual-checklist.md` 走一遍
